## M1 通用编队引擎（`public/project-intake/universal-team.js`）

离线、可解释的规则，**不按行业枚举**，只看三类与行业无关的维度，加上用户自己写的领域、对象、成功标准与限制：

- **成果形式**（8 种）：报告/文档、表格/测算表、演示文稿、软件/程序、视觉/设计稿、计划/排期、课程/培训材料、文案/视频脚本。用户可多选；未选时从描述识别，并标明来源是 `user` 还是 `detected`。
- **工作类型**（6 种）：资料调研与核实、数据整理分析、成本与预算、资源与执行安排、对象沟通、流程规范。
- **风险领域**（7 种）：医疗健康、法律合规、金融财税、人身/生产安全、未成年人、个人信息、环境影响。识别到任一领域时：
  - 风险为高、审核为严格；
  - 增加“合规与风险审查员（…，非持证专家）”；
  - 增加对应的人工专家审查要求，核心岗位附权责边界（例如“不得给出诊断、处方或治疗结论”）；
  - 平台从不声称具备认证。

生成内容：
- **岗位**：范围协调员、“<用户领域>专业内容负责人”、各成果与工作类型岗位、软件测试、风险审查、独立复核。每个岗位都有职责、权责边界、验收标准和能力标签，团队最多 12 个岗位。超出时保留范围、负责人、风险、复核四个岗位，并提示拆分项目。
- **步骤**：澄清 → 资料 → 数据 → 核心内容 → 测算 → 执行安排 → 沟通 → 流程 → 制作成品 → 测试 → 风险检查 → 独立复核。工具只用目录已有的工具 ID，由能力中心如实判定是否可用。
- **交付检查项**：用户的成功标准（来源 `user`）加规则默认项（来源 `rule`），全部为 `not_verified`。复核步骤的检查标准会逐条列出这些检查项。
- **澄清**：缺领域、成果形式或成功标准时为 `needs_clarification`，属必须补充项，此时 `readyForAutomatedExecution=false`，但仍可编辑、导出、保存草案。缺对象或限制、有风险领域、描述过简时为建议补充项。领域未知时显示“（领域待确认）”，不猜测。

## M2 接入普通用户路径（`project-intake`）

- **第 2 步“项目类型”**：首位固定为“通用编队”。无强匹配（得分<5）时，提示“没有找到与你的领域明确匹配的模板”，模板改称“参考样例（未匹配）”。仅命中个别短关键词时标“弱匹配，请确认”。只有多关键词命中才标“关键词匹配”。
- **第 3 步（通用编队）**：填写领域、成功标准、限制、风险，勾选成果形式；可重新生成建议，并显示分析结果和待澄清问题。
- **第 4、5 步**：每个岗位可编辑名称、职责、权责边界、验收标准；每个步骤可编辑名称、成果、检查标准，目录模板同样适用。编辑只保存与建议不同的字段。
- **第 6 步**：显示通用编队状态、交付检查项和人工专家审查；新增“导出可再编辑草案”。第 1 步可“导入草案 JSON”。草案文件只含用户输入，不含模型分配、连接或密钥；导入时逐项校验。
- **保存进工作台**：沿用既有接口 `POST /api/v2/intake/projects`。服务端用同一个 `engine.buildPlan` 生成方案，`server.js` 与 `lib/v2-api.js` 零改动。保存不调用模型、不启动运行。

`engine.buildPlan` 向后兼容：只新增可选输入 `templateId:'universal'`、`universal`、`roleEdits`、`stepEdits`，以及输出 `generation`、`universal`。旧目录模板的输出不变，测试逐个模板验证。编辑只接受已有 ID 与有长度上限的字符串；`__proto__`、非字符串、空名称、超过 40 项均拒绝。

## 测试（M3）

- `tests/claude-universal-intake.test.js`（9 项）：
  - 3 个目录中从未出现的行业：宠物殡葬与纪念服务、农业无人机植保、非遗竹编直播电商。验证它们没有强匹配，且岗位集合、工具集合、风险处理两两不同。
  - 高风险（医疗、未成年人、金融）必须安排人工专家；信息不足时为 `needs_clarification`，并阻止自动执行。
  - 编辑的正例与反例；XSS 与越界输入；草案导出、导入往返及畸形文件拒绝；23 个旧模板回归。
  - 真实 server（E3）：认证 401、生成方案、保存、读回、坏编辑返回 400、零模型请求与零账本行。
- `tests/ui/claude-universal-intake.e2e.js`（真实 Chromium + 真实 server）：
  - 3 个陌生行业完整走完 6 步，第 3 步先显示需要澄清，补充后变为可编辑草案；在页面上编辑岗位和步骤，提示词中能看到编辑结果。
  - 导出草案 → 重置 → 导入 → 编辑仍在 → 保存进工作台，经 API 读回。
  - 畸形文件导入被拒；XSS 文本只作为文字显示；模糊目标显示需要澄清；熟悉目标（软件）回归正常；零模型请求；页面无报错；截图与证据 JSON 写入 `UI_SHOTS`。
- 专属 CI：`.github/workflows/claude-universal-intake-r44.yml`。

## 已知限制与未来合流胶水

- 项目存储结构没有 `universal` 字段：保存后，交付检查项保留在复核步骤的检查标准里，`intake.projectType='universal'` 和风险等级也会保留，但待澄清问题与人工专家审查列表只在立项方案中。如需在工作台完整展示，需要修改 `lib/project-engine.js` 或 `lib/v2-api.js`（共享文件），本包未改，留待集成时决定。
- 第 6 步“尚未验证所需工具”的静态提示，来自既有逻辑（浏览器端不知道服务器的工具清单），与下方的服务端实时检查可能不一致，以实时检查为准。这不是本包引入的问题。
- 规则基于中文关键词，英文或其他语言的目标识别有限；识别不到时会进入澄清，不会套用模板。
- NOT_RUN：真实模型生成或补全团队（E4）、真实用户可用性研究（E5）、领域专家对岗位合理性的评审。
