# 前后台分离（B8）：两类账号、权限、每月额度

## 两类账号

| | 管理员 | 使用者 |
|---|---|---|
| 存放 | `DATA/auth.json`（不变，单管理员，scrypt） | SQLite `users` 表（schema v5，scrypt，只存盐和哈希） |
| 登录页 | `/admin-login.html`（`/admin/login` 跳转到这里），页面写明“这是管理后台” | `/login.html`：用户名 + 密码 |
| 登录接口 | `POST /api/auth/login`、首次设置 `POST /api/auth/setup` | `POST /api/auth/user-login` |
| 能去哪里 | 全部页面与接口，包括前台 | 只有 `/workspace.html`（简单模式）、`/panel.html`（大屏） |

- 两种登录共用同一套失败限流和锁定；会话都是 HttpOnly、SameSite=Strict 的 Cookie，空闲超时和绝对过期规则相同。
- 管理员停用使用者、或者重置使用者密码时，这个使用者的所有会话立刻失效。停用或删除的使用者在下一次请求时就按未登录处理。
- 使用者不能修改自己的密码。忘记密码时由管理员在后台「使用者」页面重置。

## 权限

- 后台页面对使用者一律返回 403：`admin.html`、`capabilities.html`、`project-intake.html`、旧工作台，以及它们专用的脚本。
- 后台接口对使用者一律返回 403，并说明“这是管理后台功能，使用者账号不能访问”。包括：模型、Key、价格、团队、工具、Skill、MCP、能力中心、系统账本、立项向导、上报凭证、会话管理、旧版 `/api/run`、使用者管理。
- 使用者能用的接口只有 `lib/v2-api.js` 里的 `FRONT_ROUTES`：`/me`、`/tasks`、项目、运行、资料、成果下载。
  - 每个项目或运行路径都会检查所有者（`projects.owner_id`）。访问别人的项目、运行、资料或成果，一律返回 404，不透露对方的项目是否存在。
  - `/api/v2/me` 只给出管理员已测通的模型，不含 Key、Key 提示、环境变量名或备注。
- 使用者的批准里不能授权任何工具。单价一律由服务器按登记价格重填，使用者发来的单价不被采用，所以使用者无法压低预算计算用的单价。
- 实时事件流对使用者按匿名级别脱敏：不含任何人的任务标题、项目 ID 或运行 ID。项目和工具的明细事件仍然只发给管理员。
- 只读大屏会话、上报凭证、同源检查、会话撤销的行为都不变。

## 每月额度

- 每个使用者有每月人民币上限，按整数分存储。“本月”指北京时间（UTC+8）的自然月。
- 本月已花费按费用发生的时间计算，而不是按运行的创建时间（AUD-C159-01 修复）：
  - 本月写入账本的所有费用都算，不管运行是哪个月创建的。账本里每次调用结算都有一行，重启时按保守预留记下的未知费用也是一行。
  - 再加上所有还可能花钱的运行（不管哪个月创建，比如上个月的运行在本月返工）本轮剩余的已批准上限：本轮开始时的费用 + 本轮批准上限 − 已记费用，并且不低于正在预留的金额。
  - 所以上个月的运行在本月返工时，这一轮按已批准的上限计入本月；结束后改按本月实际记账的费用计。
- 引擎账本以美元记账，换算成人民币时用与新建页相同的固定汇率 7.5（故意高于市价），并向上取整到分。这是估算，不等于厂商账单。
- 开始运行和每次返工之前，服务器都会检查额度。同一个使用者的检查和启动按顺序串行执行，两次很快的点击不能同时通过：
  - 已花费达到上限：返回 402，提示“本月额度已用完，请联系管理员”。
  - 再加上这次的上限会超额：返回 402，提示“本月额度只剩 ¥X，这次最多要花 ¥Y……”。
- 这道检查只会收紧，不会放宽原有门禁：每次运行仍要确认人民币金额，引擎的批准、预留和超支即停全部照旧。
- 运行过的项目，使用者不能删除，以免抹掉费用记录。删除需要管理员操作。

## 数据库迁移 v4 → v5 与回滚

- 新程序启动时，如果发现 v4 数据库，会先在 DATA 目录写一份私有的一致备份 `projects.sqlite.pre-v5-<时间>.bak`（权限 0600），然后在一个事务里新建 `users` 表和两个索引。迁移失败时整体回滚，数据库保持 v4，备份保留。
- **回滚到 B8 之前的版本：**
  1. 停止唯一实例。
  2. 归档当前完整的 DATA 目录。
  3. 用 `pre-v5` 备份替换 `projects.sqlite`。
  4. 部署旧代码，再启动。
- 旧程序拒绝打开 v5 数据库（`schema_newer`），所以不能只换代码。
- 回滚会丢失 v5 之后新建的使用者，以及他们在 v5 之后的项目和运行记录。如果要保留这些数据，就不要回滚。
- 不要只复制主 SQLite 文件而遗漏活跃的 WAL 文件；完整步骤见 DEPLOYMENT。

## 测试

- `tests/b8-users-store.test.js`：v4 → v5 升级与备份、v5 迁移失败回滚、账号（数据库文件里没有明文密码）、额度口径与北京时间月份，以及跨月返工（AUD-C159-01）。
- `tests/b8-split.test.js`：真实 server.js 加本地 Mock 模型。覆盖 403 矩阵（7 个后台页面、50 个后台接口）、两个使用者互相隔离、额度（进行中的运行按上限计、返工也受限）、停用和重置密码后会话立即失效、管理员功能回归。
- `tests/b8-split.test.js` 另有一项 AUD-C159-01：上个月的运行在本月返工，与一个新运行并发提交，月上限 ¥2 时只能通过一个。
- `npm run test:b8`：Chromium 浏览器，10 项检查，覆盖两类账号的主流程，以及跨月返工后新建页显示的剩余额度。
