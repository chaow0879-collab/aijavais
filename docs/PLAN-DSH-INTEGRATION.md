# 规划：吸收 DeepSeek Harness 能力 + 多任务并行内核

> 状态：**第③层"留口子"规划**（负责人 2026-11-10 优先级：① 自动化 → ② 平台上线 → ③ 其余留口子）。本规划不排任务、不占权重，只在为①②改动代码时预留扩展接口（模型适配器注册表、运行池抽象、任务依赖字段、远程 MCP 传输接口）。参考源码见 `vendor/deepseek-harness/`（MIT，提交 fcc0ad4）。

## 1. 结论

1. **不整体搬运 DSH，也不重造一个 Harness。** DSH 是 2 万多文件的 TypeScript 单体仓库，深度依赖 Cordis 插件运行时。我们只移植体积小、逻辑独立的核心算法（约 2.9k 行参考源码），重写成纯 JS，保持零依赖。这符合 #26 的要求："不复刻 Harness，差异化在普通用户门槛与交付"。
2. **算力外置，自己的服务器只做编排。**
   - 模型推理走 DeepSeek / 通义 API，按 token 计费，不需要自建 GPU。
   - 重型工具（搜索、浏览器、文档转换等）优先接**远程托管的 MCP 服务**（streamable-http）。计算发生在工具提供方，我们 1 核 / 2GB 的服务器只负责调度、存储和界面。
   - 代价与边界：数据会发送给第三方 MCP 服务，必须做允许名单、凭据模板化（`${credential:REF}`，不落明文）和逐工具授权；免费额度和稳定性要实测，并记入 E4。
3. **多任务并行是平台长期要求（第③层）。** 上线版沿用现有能力：多项目可同时运行（全局 ≤3），其余并行改造留口子。 目标效果类似 Claude 的多 Agent：A 项目执行时可以新建并运行 B 项目；同一项目内互不依赖的岗位也能同时工作。

## 2. 多任务并行：现状与目标

| 层级 | 现状（代码事实） | 目标 | 借鉴 |
|---|---|---|---|
| 跨项目 | 已支持多个项目同时运行，但全局硬上限 3 个，第 4 个直接 429 拒绝（`lib/project-engine.js:208`），不排队 | 按用户、按套餐分配并发池；超出时进入 `queued` 并自动顺延，界面显示排队位置 | `activation.ts` 槽位池 |
| 项目内 | 步骤严格串行（`lib/project-engine.js:343`） | 岗位任务组成依赖图（blockedBy），无依赖的岗位并行执行，有界并发，互斥步骤作为屏障 | `task-graph.ts`、`batch.ts` |
| 多 Agent 协作 | 前序输出交接，没有共享任务板 | 共享任务板：领取 / 完成 / 重开 / 指派 / 依赖，只有负责人或 Lead 能改；状态持久化到 SQLite | `task-board.ts` |
| 用户 | 单管理员 | 普通用户账户与隔离（MVP-B 前置，分期） | —（自研） |
| 可视化 | HALOFLUX 展示单次运行 | 多项目、多岗位并行事件同屏 | — |

**不变约束**：预算与审批仍按运行、按岗位逐项生效；取消、恢复都不自动重放；并发上限可配置但必须有界。CLAUDE.md 中"每项目 1–12 岗位、1–30 步"的约束保留。

## 3. 移植清单（按价值排序）

| # | 模块 | 落地位置（规划） | 价值 |
|---|---|---|---|
| P1 | 任务依赖图 + 就绪判定 | `lib/task-graph.js` | 项目内并行的基础 |
| P2 | 并发槽位池 + 排队 | `lib/run-pool.js`（替换全局 3） | 多项目并行不再被拒 |
| P3 | 有界并行调度（互斥屏障） | `lib/project-engine.js` 执行层 | 岗位并行执行 |
| P4 | 共享任务板状态机 | `lib/task-board.js` + SQLite 迁移 | 多 Agent 协作与可追溯 |
| P5 | DeepSeek 原生客户端（错误分类、用量、缓存 token、计价） | `lib/llm/deepseek.js` | E4 真实调用的质量基础 |
| P6 | 重试策略 + 流组装 | `lib/llm/retry.js`、`assembler.js` | 稳定性 |
| P7 | 检查点策略 | `lib/project-store.js` | 崩溃恢复（与现有"不自动重放"一致） |
| P8 | 工具输出裁剪 + token 估算 + 摘要压缩 | `lib/context/` | 降低长任务 token 消耗 |
| P9 | 远程 MCP（streamable-http）客户端 | `lib/tools-v2.js` 扩展 | 算力外置、工具生态 |

## 4. 排期（接入现有规划 #10 草案 #9）

1. 自动化第一里程碑通过（预计 11-11）。
2. **收敛重整包**：合并成一套规划器、一套前端、一套事件；完成文档收敛与 CI 拆分。
3. **并行内核包（本规划 P1–P4）**：多项目排队 + 项目内岗位并行 + 共享任务板。验收标准是 A、B 两个项目同时运行，且同一项目内至少 2 个岗位并行；用 E2/E3 测试与独立审计确认。
4. **模型与工具包（P5–P9）**：DeepSeek 原生客户端 + 远程 MCP，然后做首次真实 E4（需要负责人提供 API Key，预算由总指挥按"最小可验证"原则设定）。
5. 之后进入 MVP-A / MVP-B 路线。首个场景由总指挥决定，并写明理由。

## 5. 对照与退出条件

每个包完成后，都与 DSH 本体做一次对照：同一任务比较启动耗时、人工介入次数、成功率、成本。若某项能力直接用 DSH 明显更好、我们自研没有优势，就改为把 DSH（其 SDK / 子代理后端）作为执行后端接入，不再自研（#26 商业取舍门槛）。
