# REPO NEXUS · 通用团队文件协作与分发平台（v2 开发基线）

由用户决定复用原 GitHub 仓库 `chaow0879-collab/aijavais` 的全新项目（原 AIJAVAIS 开发已停止）；这是 Node.js 22+、零运行时第三方依赖程序。**禁止删除这个已经转用的仓库**。面向**任何行业/团队**，人力资源、产品研发、设计、管理、教育等仅是可建立的项目空间示例，**不是产品预设行业限制**。

## 当前已实现（真实接口 + 测试）

- 科技风中文响应式界面：文件矩阵、历史仓库、分发中心、团队与操作审计。
- 管理员与团队成员：管理员可添加 editor/viewer 账号，密码使用 scrypt 单向加盐哈希；管理员/编辑者可上传，浏览者只读。
- 项目空间：创建、列出，按项目分类文件；目前**所有已登录团队成员可访问所有项目**，精细 ACL 留待后续。
- 文件多类型上传（文档、办公文件、图片、音视频、压缩包等）与上传进度；服务端保存原始二进制，不执行上传的代码。
- **同项目同名覆盖自动归档**：每次上传会产生不可变新文件版本、SHA256、上传人、时间、版本号；上一个当前版自动转为历史归档，不物理删除。支持主动归档/取消归档、历史版本下载、以“新版本”方式恢复旧版。
- 版本对比：显示元数据（哈希是否相同、大小差异）；**还没有实现 Word/PDF/Excel/ZIP 文件内容的智能差异/合并**，不能宣称实现了二进制合并。
- 蓝奏云式分发：高熵随机链接、密码、到期日、次数上限、撤销、匿名不可列目录；链接绑定**具体文件版本**，不是自动指向最新版本。新文件覆盖后，已发出的旧版链接仍指向旧版，需人工撤销或重新发新链接。
- 审计记录：登录、成员创建、上传与覆盖、恢复、归档、分享创建/撤销；普通匿名下载没有账户身份识别。
- 旧版兼容迁移：若 `metadata.json` 为 v1，现有文件与分享数据保留，在启动时原位升级为 v2 结构。

## 本地运行

```bash
export REPO_ADMIN_PASSWORD='换成独立的至少12字符强密码'
export REPO_DATA_DIR='./private-data'
export REPO_COOKIE_SECURE=false
export REPO_BASE_URL='http://127.0.0.1:8891'
node server.mjs
```

浏览器打开 `http://127.0.0.1:8891`，管理员为 `admin`，密码由环境变量定义。**请勿把密码写进源代码、Git 仓库或聊天提示词。**

测试：

```bash
npm test
```

## 安全与数据边界

- 原始文件保存在 `REPO_DATA_DIR/files/`，不是 web root；目录与写入文件使用最小权限。`metadata.json` 存储业务元数据、成员的密码哈希和分享链接哈希。此目录**不得提交到 Git**。
- 默认监听 `127.0.0.1:8891`（启动脚本由 `BIND_ADDRESS`, `PORT` 配置），生产通过独立域名 `https://repo.ailp.fun` 的 HTTPS 反向代理访问。
- 生产环境保持 `REPO_COOKIE_SECURE=true`；会话 HttpOnly + SameSite=Strict，变更接口校验 CSRF；下载强制附件流，不开放目录索引。
- **限制**：目前使用单进程 JSON 元数据，不具备数据库事务、跨进程一致性、真正不可篡改审计、断点续传、存储配额、服务端防病毒扫描、异地备份。正式团队生产上线前请由 Codex 迁移 SQLite + 事务、增强大文件上传、可靠备份/恢复与回归测试。
- 该版本是**开发基线**，不是已经部署或完成全面安全审计的正式商用版本。

## 部署隔离原则

服务器 `192.129.232.56`，目标域名 `repo.ailp.fun`。SSH 连接尚未验证成功。先在服务器做**只读资产清单**，确认真实 SSH、现有服务、磁盘、Caddy 虚拟站点、证书和端口；再把本项目放在独立账户/目录/端口/数据卷。**不要修改、删除或重启任何与本项目无关的站点/服务**。任何共享反向代理变更需先备份、验证、最小化 reload 并对旧站冒烟；失败立即回滚。

停止旧 AIJAVAIS **服务器应用** 是另一独立操作：在确认服务/路径确实专属旧项目、不会牵连其他网站和必要数据后才可执行。旧的 GitHub 仓库已改为本项目代码仓库，**不得删除**；旧项目历史提交可能仍在 Git 历史中。
